# Grill UI

Факты добывает агент, решения принимает владелец. Основная ветка ведёт дерево
решений. Отдельный чат помогает разобраться в одном вопросе и не передаёт свою
историю основной ветке.

## Подготовка

Прочитай [references/runtime.md](references/runtime.md) перед запуском.
Проверь Python и агентский CLI (Codex или Claude Code), его авторизацию и
model/effort вызывающей сессии. Используй bundled runtime. В Herdr открывай
TUI во вкладке; вне Herdr запусти сервер раунда и попроси владельца открыть
TUI в своём терминале по runtime reference. Не переписывай мост к CLI на
каждом раунде. Если CLI недоступен, назови причину.

## Механика grill

1. Учти принятые решения и разрешения. Открывай решение повторно только при
   новых фактах, меняющих его условия, и объясни изменение.
2. Найди факты в окружении сам. Перед вопросом о реализации посмотри, как
   аналогичная задача уже решена рядом. Спрашивай намерения, приоритеты,
   границы и выбор между подходящими вариантами.
3. Построй дерево предпосылок. Frontier состоит из вопросов, чьи предпосылки
   уже улажены. Покажи весь frontier одним раундом. Вопросы, зависящие от
   открытых ответов этого раунда, отложи до следующего.
4. Для каждого вопроса дай рекомендацию и её основание. Предложи выбор,
   когда есть полезные варианты. Всегда оставляй свободный ответ.
5. Незавершённый поиск блокирует только зависимые вопросы. Остальной frontier
   показывай сразу. Отличай неизвестный факт от предположения.

## Показать раунд

1. Прочитай [references/round-format.md](references/round-format.md) и создай
   JSON текущего frontier. В общий контекст включи цель, ограничения и принятые
   решения. В контекст каждого вопроса добавь необходимые факты, основания
   вариантов, выдержки из доступных источников и пути к ним. Чат не получает
   историю основной ветки автоматически. Если источник доступен только через
   инструменты основной ветки, передай релевантную выдержку с атрибуцией.
2. Создай отдельный каталог раунда вне продуктовых файлов. Выполни `init`.
   В Herdr используй `grill_herdr.py open`: один новый **tab** с названием Grill
   в том же workspace и на том же сервере, где работает вызывающий агент.
   Не создавай split-pane или новый workspace. Один tab содержит весь frontier
   этого раунда. Не запускай интерфейс на машине клиента вместо машины агента.
   Вне Herdr запусти `serve` и дай владельцу команду запуска TUI по runtime reference.
3. Объясни: ответь на все вопросы и нажми «Отправить все ответы». В Herdr
   TUI после отправки сам вводит в панель агента «Готово: ответы Grill
   отправлены. Файл: …/answers.json» с Enter, дописывая к уже набранному там тексту; это начинает
   новый ход. Поэтому после объяснения заверши ход, не держи его ожиданием.
   Если TUI сообщил, что написать агенту не удалось, или TUI запущен вне Herdr,
   владелец возвращается и пишет «Готово» сам.
4. Если ждёшь внутри хода, используй `grill_herdr.py wait --timeout 45` или `status`.
   Эти команды возвращают только готовность и счётчик. Не читай промежуточные
   ответы, `state.json`, `tui-pending.json` или CLI-транскрипты. Можно продолжать
   независимый поиск фактов. Молчание и таймер не означают ответа.
5. После `submitted: true` прочитай только `answers.json` и проверь round ID
   и полноту списка. Там ID вопросов, ID выбранных вариантов и окончательный
   текст владельца; формулировки бери из своего исходного round JSON.
6. В режиме Herdr после чтения результата обязательно выполни
   `grill_herdr.py finish` для этого session-каталога. Команда закроет только созданный tab и остановит
   его сервер, сохранив данные. Если проверка принадлежности отказала, сообщи
   причину; не закрывай другую вкладку вручную по совпавшему номеру или названию.
   Вне Herdr останови свой процесс сервера по runtime reference.
7. Пересобери дерево. При новых вопросах создай новый каталог и новый tab Grill
   после завершения предыдущего. Не меняй вопросы отправленного раунда.
   Не закрывай неотправленный раунд по таймеру или при отключении клиента.

## Отдельные обсуждения

Интерфейс показывает список вопросов слева, содержание и ответ в центре, чат
справа. Первое отправленное сообщение создаёт отдельную сессию CLI.
Последующие сообщения продолжают конкретный ID через resume этого CLI.
По умолчанию чаты используют тот же харнесс, model и reasoning effort, что
текущий родительский ход; локальный конфиг сам по себе не доказывает совпадение.
Runtime читает метаданные родительского хода и прекращает подготовку, если
параметры неизвестны. Владелец может выбрать другой харнесс, модель и effort
в списках над чатом (F5); это его решение, не твоё. Не подменяй модель при ошибке доступности.

Встроенные collaboration subagents не дают этому интерфейсу пользовательский чат.
Не создавай их для каждого вопроса. Чаты запускает локальный сервер по действию
пользователя. Код сервера ограничивает один активный ход на вопрос.

«Черновик» получает текст ответа из отдельного чата. «Вставить в мой
ответ» переносит его в редактируемое поле. Только пользователь подтверждает
ответ и отправляет раунд. Переписка, промежуточные черновики и скрытые
рассуждения не включаются в `answers.json`. Основной агент не читает
`state.json` и CLI-транскрипты ради продолжения grill.

## Завершение

Пустой frontier не означает конец, если остаются ветки, ожидающие поиска.
Заверши разбор, когда каждая ветка улажена, блокирующих неизвестных фактов нет,
а допущения названы и согласованы. Собери цель, границы, решения с основаниями
и допущения. Дождись подтверждения общей картины, затем выполняй уже разрешённую
работу. Не требуй повторного подтверждения той же картины.

До подтверждения не меняй продуктовый код. Подготовка интерфейса grill и его
локальных данных разрешена самим запросом на визуальный grill.

Для записи в `DECISIONS.md` используй уже данное разрешение или сначала получи
его. Подтверждение общей картины не разрешает такую запись само по себе.
Записывай решение только если его трудно откатить, без контекста оно выглядит
странно и у владельца был настоящий выбор. Три предложения: контекст, решение,
почему. Отвергнутый вариант добавляй только при неочевидной причине отказа.
Остальное оставляй в разговоре. Не создавай каталог ADR, пока единый файл
читается целиком; разделяй его только при разрешённой работе с документацией.
