# Данные раунда

Передай JSON UTF-8 для каждого раунда. Все строки отображаются как текст, HTML не исполняется.
Пример находится в `assets/example-round.json`.

Обязательные поля раунда: `id`, `title`, `goal`, `context`, `questions`.
`accepted_decisions` содержит согласованные решения прошлых раундов, если они
есть. В общем контексте оставь факты и ограничения, нужные каждому чату.
Вопросы одного раунда независимы; `depends_on` может ссылаться только на
уже решённые вопросы прошлых раундов этого grill, не на вопросы того же раунда.
ID раунда и ID вопросов уникальны во всём grill: `add-round` отклонит повтор.

Вопрос содержит:

| Поле | Значение |
|---|---|
| id | Стабильный ID, уникальный во всём grill |
| title | Короткий заголовок для списка слева |
| body | Полное описание вопроса и причины выбора |
| recommendation | Рекомендация и основание, обязательны |
| context | Необходимые отдельному чату факты, выдержки и атрибуция |
| mode | single по умолчанию, multiple или text |
| options | Массив объектов id, label и необязательного description |
| recommended | Необязательный список ID рекомендованных вариантов; в single не больше одного |
| depends_on | Необязательный список ID улаженных предпосылок из прошлых раундов |

`single` допускает один вариант, `multiple` несколько, `text` свободный
ответ. Свободное поле есть при любом mode. Варианты не выбраны заранее.
Пользователь может снять выбор и ответить только текстом. Рекомендация не
означает согласия пользователя. Варианты из `recommended` интерфейс помечает
янтарной полосой справа и подписью «совет агента», не выбирая их; указывай их всегда, когда
рекомендация совпадает с вариантами.

Не меняй вопрос и его контекст после запуска: ветка чата уже относится к
конкретной формулировке. Если новые факты существенно изменили вопрос,
объясни изменение и задай его в следующем раунде с новым ID. Прежний ответ
остаётся в истории grill.

## Нумерация

Сервер нумерует вопросы сквозь весь grill по порядку раундов и вопросов в них:
второй раунд из двух вопросов после трёх вопросов первого получает номера 4 и 5.
Номер виден в списке слева («4. Заголовок») и есть в файлах результата. Опирайся
на `question_id`; номер нужен, чтобы говорить с владельцем об одном вопросе.

## Подтверждение и результаты

Правка снимает подтверждение. Кнопка «Подтвердить ответ» сохраняет ответ с
`confirmed: true`. Пустое поле без выбора нельзя подтвердить.
Отправка раунда возможна только когда каждый его ответ подтверждён и в его
вопросах нет активных обсуждений. Каждая отправка пишет новый неизменяемый
файл `session/submissions/NNNN.json` только с новыми данными:

```json
{
  "round_id": "r2",
  "submitted_at": 0,
  "answers": [
    {
      "question_id": "Q4",
      "number": 4,
      "selected": ["local"],
      "text": "Без синхронизации в первой версии."
    }
  ],
  "reopen": [
    {
      "question_id": "Q2",
      "number": 2,
      "round_id": "r1",
      "reason": "Теги всё-таки нужны: статьи по трём темам."
    }
  ]
}
```

`submitted_at` имеет формат Unix timestamp. `answers` содержит только
отправленный раунд. Если открытого раунда нет, владелец отправляет одни
просьбы о пересмотре: тогда `round_id` равен `null`, а `answers` пуст.
Путь к новому файлу приходит в «Готово» и в `result_file` у `status`;
прошлые файлы не меняются и повторно не читаются.

Основной агент получает выбор и свободный ответ вместе. Если они противоречат
друг другу, задай уточнение в следующем frontier. Чат и автоматически
предложенный черновик не доказывают выбор владельца.

Результат содержит только ID выбранных вариантов. Их формулировки уже есть
в исходном round JSON основного агента; описания и история чатов не дублируются.

## Пересмотр

Отправленные ответы в интерфейсе только для чтения. Кнопка «Пересмотреть»
у такого вопроса просит причину; без неё запрос не сохраняется. Запрос виден
у вопроса и отмечен в списке «↺», владелец может отменить его до отправки.
Запросы уходят со следующей отправкой раунда в разделе `reopen`, а без
открытого раунда кнопкой «Отправить пересмотр».

Запрос не отменяет решение сам. Реши по правилу 1 SKILL.md: причина может
оказаться новым фактом, меняющим условия. Открытое решение спроси в следующем
раунде с новым ID и объясни, что изменилось. Если решение остаётся, объясни
владельцу почему.
