# Локальный runtime

## Проверка

Нужны Linux или macOS, Python 3.11+ и хотя бы один установленный,
авторизованный агентский CLI: Codex или Claude Code. Сервер использует POSIX
process groups и flock. Проверь тот CLI, в котором работаешь:

```sh
python3 --version
codex --version && codex login status          # Codex
claude --version && claude auth status         # Claude Code
```

Авторизация использует существующий вход CLI, отдельного API key нет.
Адаптеры лежат в `scripts/grill_harness.py`:

| | Codex | Claude Code |
|---|---|---|
| Ход | `codex exec --json -m M -c model_reasoning_effort=E -` | `claude -p --output-format stream-json --verbose --include-partial-messages --model M --effort E` |
| Продолжение | `resume <thread_id>` | `--resume <session_id>` |
| Только чтение | `sandbox_mode="read-only"`, `approval_policy="never"` | `--tools Read,Grep,Glob,WebSearch,WebFetch --strict-mcp-config --disable-slash-commands` |
| Веб | `-c web_search="live"` (`--search` есть только у интерактивного `codex`) | `--allowedTools WebSearch,WebFetch`: без него `-p` отклоняет их запрос разрешения |
| События | `thread.started`, `item.completed`/`agent_message`, `turn.failed`, `error` | `system`/`init`, `stream_event`/`content_block_delta`/`text_delta`, `result` (`is_error`) |
| Каталог моделей | `codex debug models` | алиасы `opus`, `sonnet`, `haiku`; effort из `claude --help` |

Дочерний CLI запускается без переменных родительской сессии (`CODEX_THREAD_ID`,
`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID` и т. п.), чтобы не считать себя
вложенным агентом и не видеть канал родителя.

## Терминал и Herdr

Прочитай этот раздел для режима TUI. Нужен Herdr 0.9+ на сервере агента.
Сохранённые машины `herdr machine` поддерживаются: клиент может находиться
на Linux или Mac, TUI и агентские CLI работают на хосте выбранного workspace.
Идентификаторы привязаны к серверному socket, а не только к `w1:t2`.

TUI работает в отдельном окружении `${XDG_DATA_HOME:-~/.local/share}/grill-ui/venv`
с закреплённым Textual. `open` и действие плагина создают его сами, если его
нет или `requirements.txt` изменился после установки: в venv хранится
sha256 файла, с которым он собран. Установщик использует uv, если он есть,
иначе venv/pip текущего Python 3.11+, и нуждается в сети. Ход установки идёт
в stderr, stdout `open` остаётся JSON. На Mac системный Python может быть
старее; тогда нужен uv. Установить заранее или повторить после ошибки:

```sh
python3 "$SKILL_DIR/scripts/grill_herdr.py" install
herdr plugin link "$SKILL_DIR"
```

Плагин необязателен для запуска из скилла.
Его действие `local.grill-ui.reopen` открывает последний grill текущего workspace.
Если их несколько, используй `open --session` с точным путём.

Один grill занимает один session-каталог, один сервер и один tab Grill на все
раунды. После `init` первого раунда:

```sh
python3 "$SKILL_DIR/scripts/grill_herdr.py" open --session "$GRILL_DIR/session" --focus
python3 "$SKILL_DIR/scripts/grill_herdr.py" wait --session "$GRILL_DIR/session" --timeout 45
```

Каждый следующий раунд добавляется в ту же сессию, затем `open` показывает его:

```sh
python3 "$SKILL_DIR/scripts/grill_ui.py" add-round --session "$GRILL_DIR/session" --round "$GRILL_DIR/r2.json"
python3 "$SKILL_DIR/scripts/grill_herdr.py" open --session "$GRILL_DIR/session" --focus
```

`open` требует `HERDR_ENV=1` и контекст вызывающей панели. Он создаёт tab Grill
в текущем workspace, запускает отдельный сервер и TUI. Без `--focus` сохраняет
текущий фокус. `open` ждёт, пока TUI возьмёт `tui.lock`. Новая оболочка
может потерять Enter, набранный до первого приглашения; тогда, если в панели
ничего не запущено, `open` один раз повторяет Enter. Если TUI не поднялся за
20 секунд, `open` сообщает ошибку. Повторный `open` использует тот же tab; после закрытия вкладки
вручную создаёт новый для той же сессии. Завершённый через `finish` grill
повторно не открывается. Сам TUI можно запустить без Herdr через Python
установленного venv: `scripts/grill_tui.py --session SESSION`.

Список слева прокручивается и содержит все раунды grill. Заголовки «Раунд 2 ·
отправлен» и «Раунд 3 · текущий» не выбираются, стрелки их пропускают. Номера
вопросов сквозные («7. Заголовок»), строка над вопросом показывает номер и
раунд. Отметки: ✓ подтверждён, ◐ черновик, ○ нет ответа, ↺ запрошен пересмотр.
Пока агент готовит следующий раунд, в центре экран ожидания, а в конце списка
строка «Агент готовит раунд»; прошлые вопросы и их чаты остаются доступны.
Новый раунд, добавленный при работающем сервере, TUI показывает сам.

Внутри tab: мышь, Tab, стрелки. F2 скрывает и показывает список вопросов,
F7 скрывает и показывает обсуждение, F3 разворачивает чат на всю ширину,
F4 переходит к ответу, F5 к выбору агента, F6 к сообщению. F-клавиши нажимаются
без prefix Herdr и работают из любого поля. Пробел в списке вариантов
переключает выбор. Enter в списке вариантов или в поле ответа подтверждает
непустой ответ и переходит к следующему неподтверждённому вопросу текущего раунда; при пустом
ответе ничего не делает. Когда подтверждены все, фокус встаёт на «Отправить все
ответы». Enter в поле сообщения отправляет его агенту. Shift+Enter или Ctrl+J
переносит строку. Пока агент отвечает, его ответ появляется в чате по мере
написания, а над полем сообщения видно время хода и последнее действие.

Выпадающие списки над чатом задают харнесс, модель и effort для новых чатов и
применяются сразу. Списки берутся из установленных CLI при старте сервера:
модели Codex из `codex debug models`, для Claude Code алиасы opus/sonnet/haiku
и effort из `claude --help`. Новая модель появляется без правки скилла; модель
вне списка вводится через «Другая модель…» и применяется по Enter. Начатый чат
продолжает агент, который хранит его историю; под списками видно, какой, а
кнопка «Новый чат» начинает обсуждение этого вопроса заново с выбранным агентом.
Кнопка «Подтвердить ответ» подтверждает один вопрос без перехода; «Отправить все
ответы» отправляет весь раунд, пишет «Готово» агенту и переключает на его вкладку. Ctrl+Q закрывает TUI, сервер продолжает работать.

Отправленные вопросы только для чтения: выбор и текст видны, но не меняются.
Их чаты продолжаются: «Отправить», «Остановить» и «Черновик» работают,
«Вставить в мой ответ» нет. Кнопка «Пересмотреть» у отправленного вопроса
открывает поле причины; Enter или «Попросить пересмотр» сохраняет непустую
причину, «Отменить пересмотр» снимает запрос до отправки. Запросы уходят со
следующей отправкой раунда; если открытого раунда нет, та же кнопка в шапке
называется «Отправить пересмотр» и отправляет их одни. После `finish` чаты
закрыты.
Черновики сохраняются сервером; при потере связи локальный `tui-pending.json`
сохраняет ещё не доставленные правки. Повторяются только идемпотентные сохранения,
не сообщения агенту. После неоднозначной ошибки отправки проверь историю.
Второй TUI на тот же grill блокируется файловым lock.

После «Отправить все ответы» TUI вызывает `herdr pane send-text` для панели
агента текст «Готово: ответы Grill отправлены. Файл: …/submissions/0002.json» с полным
путём нового файла результата и отдельным `send-keys enter`. Путь позволяет
владельцу самому открыть файл, который прочитает агент.
Отправка одного пересмотра, без раунда, вводит «Готово: запрос на пересмотр
Grill отправлен. Файл: …».
Текст добавляется к набранному в поле ввода, а не заменяет его. Перед вводом
проверяется, что это тот же терминал, из которого открыт grill; иначе TUI
ничего не вводит и просит владельца вернуться вручную. Live handoff Herdr
(`herdr server live-handoff`) пересоздаёт socket и terminal ID, но сохраняет
ID панелей и их процессы; это обрабатывается как описано у `finish`. Уведомление отправляется
один раз, при нажатии кнопки; повторное открытие TUI его не повторяет.

`wait` ждёт отправки последнего раунда, не показывает ответы до неё и не
запускает новый ход родительского агента. При истечении таймера возвращает
текущий статус, без выбора за владельца. После отправки прочитай только новый
файл результата и покажи следующий раунд через `add-round`. Один раз в конце
grill, когда владелец подтвердил общую картину в обычном чате:

```sh
python3 "$SKILL_DIR/scripts/grill_herdr.py" finish --session "$GRILL_DIR/session"
```

`finish` требует отправленного последнего раунда и отсутствия неотправленных просьб о пересмотре. Он проверяет host, socket
и его identity, workspace, tab, pane и terminal.
Если сменилась identity socket, а TUI этого grill ещё держит `tui.lock`, это
live handoff: перезапуск сервера убил бы TUI. Тогда `open`, `finish` и ввод
«Готово» перечитывают terminal ID и обновляют `herdr.json`, если tab grill
остался с одной панелью в том же workspace, в ней работает этот TUI, а панель
агента существует с тем же shell PID. Если сервер перезапущен, TUI закрыт или
во вкладку добавлены чужие панели, команда отказывает в автоматическом закрытии. Она не завершает сервер Herdr. Данные grill остаются.
Отключение клиента не закрывает tab и не отменяет обсуждение.

## Создание grill и запуск вне Herdr

Пути ниже условные. `SKILL_DIR` обозначает каталог установленного grill-ui.
`GRILL_DIR` выбирай вне исходников продукта, например внутри локального
каталога данных агента. Он хранит контекст и переписку, не добавляй его в git.

```sh
python3 "$SKILL_DIR/scripts/grill_ui.py" init \
  --round "$GRILL_DIR/r1.json" \
  --session "$GRILL_DIR/session" \
  --cwd "$PROJECT_DIR"
python3 "$SKILL_DIR/scripts/grill_ui.py" add-round \
  --session "$GRILL_DIR/session" --round "$GRILL_DIR/r2.json"
```

`init` создаёт сессию с первым раундом и отказывает, если сессия уже есть.
`add-round` добавляет следующий раунд: требует отправленного предыдущего,
нового round ID и ID вопросов, которых ещё не было в этом grill. Если сервер
сессии работает, команда передаёт раунд ему по адресу и токену из
`server.json`, и TUI переключается сам (`"live": true`). Если сервера нет,
она меняет состояние под lock сервера (`"live": false`). Выбор агента
владельцем сохраняется между раундами; агент `init` остаётся исходным.
Session-каталог прежнего формата с одним раундом открывается как grill из
одного раунда; его `answers.json` считается первым файлом результата.

`init` определяет вызывающий харнесс по окружению и берёт model/effort его
сессии. Codex: `CODEX_THREAD_ID` и `turn_context` в каталоге sessions Codex,
плюс доступный service tier. Claude Code: `CLAUDE_CODE_SESSION_ID`, модель
из транскрипта `~/.claude/projects/*/<session>.jsonl`, effort из `CLAUDE_EFFORT`.
Разговор не копируется. Если видны обе сессии (Codex запущен внутри Claude Code
или наоборот), `init` требует `--harness codex|claude`. Точный ID родителя
передаётся через `--parent-thread`. Если metadata отсутствует, передай
`--harness`, `--model` и `--effort` из достоверных данных текущей сессии.
Не используй глобальные defaults вместо неизвестных параметров родителя.
Скрипт не редактирует конфиг.

В Herdr после `init` достаточно `grill_herdr.py open`: он сам запускает сервер
и TUI. Вне Herdr запусти сервер сам и дай владельцу команду для его терминала
на той же машине. Если venv ещё нет, сначала выполни `grill_herdr.py install`.

```sh
python3 "$SKILL_DIR/scripts/grill_ui.py" serve --session "$GRILL_DIR/session"
"${XDG_DATA_HOME:-$HOME/.local/share}/grill-ui/venv/bin/python" \
  "$SKILL_DIR/scripts/grill_tui.py" --session "$GRILL_DIR/session"
```

Вне Herdr TUI не может написать агенту «Готово»: владелец возвращается сам.

Сервер пишет адрес и токен в `session/server.json`, TUI берёт их оттуда при
каждом запросе и после перезапуска сервера подключается сам. Сервер слушает
только loopback; API проверяет токен, Host и Origin. Не публикуй server.json
или session-каталог.

Запускай сервер как длительный локальный процесс средствами своего runtime.
Если инструмент завершает процессы при окончании хода, запусти через
`subprocess.Popen(..., start_new_session=True)` с stdin=DEVNULL и отдельным
логом. Не запускай дублирующий сервер на тот же session-каталог. Сервер
живёт весь grill; останови свой процесс после подтверждения общей картины,
ответы сохранятся. `Ctrl+C` завершает сервер и активные CLI-процессы.

## Возврат ответа

```sh
python3 "$SKILL_DIR/scripts/grill_ui.py" status --session "$GRILL_DIR/session"
```

`status` выводит только ID последнего раунда (`round_id`), его `submitted`,
`confirmed` и `total`, `waiting` (открытого раунда нет, владелец ждёт
следующий), число неотправленных просьб о пересмотре (`reopen`), `finished` и путь
к последнему файлу результата (`result_file`). Проверяй по возвращению
пользователя или жди локальное событие в своём runtime. Сервер не умеет
инициировать ход родительского агента; это делает только TUI в Herdr (см. выше).

Каждая отправка пишет новый файл `session/submissions/NNNN.json`; формат в
[round-format.md](round-format.md). Основной агент читает только файл из
«Готово» или `result_file` и не перечитывает прежние. Не читай
`state.json`: он содержит частные обсуждения вопросов. Они изолированы по
контексту сессий, но не отдельной OS-средой. И CLI, и основной агент технически
имеют доступ к локальным данным в пределах своих разрешений.

## Почему отдельный процесс + resume

Для каждого вопроса сервер создаёт независимую сессию выбранного CLI. Сервер
передаёт контекст вопроса через stdin, сохраняет точный ID сессии и продолжает
её через resume. Не использует `--last`/`--continue`, fork родительской истории
или эфемерные сессии. История соседних вопросов в prompt не попадает. Сессии
Claude Code появляются в `claude --resume` для cwd проекта.

App Server также поддерживает thread/start, turn/start и thread/resume.
Для этого небольшого локального интерфейса выбран exec + resume, чтобы
обойтись Python stdlib без отдельного JSON-RPC клиента. Пока идёт ход,
сервер держит написанную часть ответа в `branch.partial`, TUI опрашивает его
каждые 0,3 с и показывает время хода и последнее действие агента из событий
CLI (команда, чтение файла, поиск). Claude Code отдаёт текст по фрагментам.
`codex exec --json` фрагментов не отдаёт: каждое завершённое `agent_message`
видно сразу, остальное в конце хода. `state.json` во время ответа пишется не
чаще раза в 0,3 с. Итоговый ответ заменяет частичный; при ошибке или остановке
в переписке остаётся то, что успело прийти.
Опрос дешёвый: сервер ведёт версию состояния и на `/api/state?since=V` без
изменений отвечает `{"unchanged": true}`; полный grill уходит только после
изменения.

Каждый вызов получает явные model/effort и read-only режим (см. таблицу выше).
Ветка предназначена для обсуждения. Чат может искать в интернете; страницы и
результаты поиска для него данные, не инструкции. У Codex read-only ограничивает
файловые команды, но не является универсальной изоляцией подключённых MCP-инструментов;
Claude Code запускается без MCP и skills. Hooks пользователя работают в обоих.
Не настраивай в этом приложении автоматическое разрешение мутаций.
Глобальные конфигурация, провайдер, hooks и MCP CLI могут отличаться от
инструментов родительского приложения. Совпадение model/effort не означает
идентичного набора инструментов. Ошибку модели покажи, не меняй модель
автоматически: сменить агента может только владелец в TUI.

## Ошибки

- Авторизация истекла: войди в нужный CLI обычным способом и повтори сообщение.
- CLI завершился с ошибкой: интерфейс покажет её и сохранит переписку.
  Повторной генерации без действия пользователя нет.
- Активный ход можно остановить. Предельная длительность хода 15 минут.
- После перезапуска сервера незавершённый ход помечается ошибкой.
  Просмотри чат перед новым сообщением: часть хода могла сохраниться в CLI.
- Нет связи с сервером: повтори `grill_herdr.py open` (вне Herdr перезапусти
  `serve`); TUI подключится сам. Несохранённое поле не считается ответом.

## Проверенные источники

Проверено на Codex CLI 0.155.1: создание сессии, JSONL event ID,
возобновление по ID, model/effort и read-only конфигурация. Каталог
`codex debug models` проверен на 0.156.1. Claude Code 2.1.281: stream-json,
`session_id` в `system/init`, resume по ID с сохранением контекста, ошибка
неизвестной модели как `result` с `is_error`. Claude Code 2.1.285:
`--include-partial-messages` (`stream_event` с `content_block_start`/`text` и
`content_block_delta`/`text_delta`), WebSearch и WebFetch в `-p` с
`--allowedTools`. Codex CLI 0.159.2: `-c web_search="live"` в `exec` и
`exec resume` (значения `disabled`, `cached`, `indexed`, `live`),
промежуточные `agent_message` до конца хода, текстовых дельт нет.

- [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
- [Codex App Server](https://learn.chatgpt.com/docs/app-server)

Базовую механику перенесли из установленного `grill/SKILL.md`: дерево,
полный frontier, рекомендации, ожидание владельца и фильтр DECISIONS.md.
Этот скилл самодостаточен; установка исходного grill не требуется.


## Проверка изменений runtime

```sh
uv pip install --python "$TUI_PYTHON" -r "$SKILL_DIR/requirements-test.txt"
"$TUI_PYTHON" -m unittest discover -s "$SKILL_DIR/scripts" -p 'test_grill*.py' -v
"$TUI_PYTHON" "$SKILL_DIR/scripts/smoke_grill.py"
```

`TUI_PYTHON` указывает на Python установленного venv. Smoke запускает отдельную
сессию Herdr со случайным именем, использует тестовый CLI вместо модели и
останавливает только свои процессы. `--remote HOST --remote-root SKILL_PATH
--remote-python PYTHON_PATH` проверяет реальное подключение через временный
профиль `herdr machine add`. На обеих сторонах нужен checkout скилла и тестовые
зависимости. Проверки включают Unicode paste, клик мышью, переподключение,
повторное открытие, продолжение чата по тому же ID, второй раунд в том же tab
с просьбой о пересмотре и «Готово» с путём нового файла, live handoff сервера
Herdr перед вводом «Готово» с Enter в панель агента и перед `finish`, установку
venv при первом `open`. Smoke использует временный `XDG_DATA_HOME`, поэтому
ставит свой venv и не трогает рабочий. Локальный клиент smoke получает отдельный `XDG_STATE_HOME`:
иначе он видит сохранённые машины владельца и переключается вслед за его
выбором. Cleanup удаляет каталог своей тестовой сессии, а копии экрана и логов
последнего прогона остаются в `$TMPDIR/grill-smoke-debug` с правами 0700.
Проверку уведомления можно запустить
без клиента: `--prepare`, затем `--control FIXTURE notify` и `cleanup`.

Textual закреплён на 8.2.8. TUI использует драйвер с координатами мыши в ячейках
и SIGWINCH, без совместного включения in-band resize / pixel mouse.
При обновлении Textual повтори PTY-проверки: переопределён приватный driver hook.
